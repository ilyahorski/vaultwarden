## Обзор проекта
Проект представляет собой RPG-движок на базе **Excalibur.js** с интерфейсом и редактором на **React**. Система использует **IndexedDB (Dexie)** для сохранения состояния мира и **EventBridge** для синхронизации между игровым движком и UI.

## Команды разработки
* **Запуск:** `npm run dev`
* **Сборка:** `npm run build`
* **Линтинг:** `npm run lint`
* **Типизация:** `npx tsc --noEmit`

## Технологический стек
* **Движок:** Excalibur.js
* **UI:** React + Tailwind CSS
* **База данных:** IndexedDB (через `gameDB` и репозитории)
* **Коммуникация:** `EventBridge` (EventEmitter)

## Архитектурные правила

### 1. Разделение ответственности
* **Excalibur (`src/excalibur/`):** Логика рендеринга, акторы, сцены, системы боя и коллизий.
* **React (`src/components/`):** UI игрока, инвентарь, меню и обертка редактора `TilemapEditorWrapper`.
* **Репозитории (`src/db/repositories/`):** Единственный слой для работы с данными. Прямое обращение к `gameDB` из компонентов запрещено.

### 2. Работа с картой и данными
* **Источник истины:** Всегда `WorldRepository`. Логика загрузки: IndexedDB -> Fallback на `interdest_map.json`.
* **Типизация:** Используй `CellData` для описания ячеек и `DuoParty` для состояния игрока.
* **Координаты:** В Excalibur используй пиксельные координаты (`x * TILE_SIZE`), в логике редактора — индексы сетки (`x, y`).

### 3. Синхронизация (React <-> Excalibur)
* Для передачи данных из Редактора в Игру используй `EventBridge.emit('editor:mapUpdated', data)`.
* Для доступа к методам Excalibur из React используй ссылки, предоставляемые через `scene:ready`.

### 4. Коллизии и проходимость
* Проходимость определяется в `MapLoader.populateTileMap`. 
* Тайлы с типами из `SOLID_TILE_TYPES` или метаданными `passable: false` должны получать `tile.solid = true`.

## Стандарты кодирования
* **TypeScript:** Строгая типизация обязательна. Избегай `any`.
* **Компоненты:** Функциональные компоненты React с хуками.

## Рабочий процесс создания карт

### Обзор системы карт
Проект использует **tilemap-editor** как единственный инструмент для создания всех игровых карт (мировая карта, города, подземелья). Карты хранятся в **IndexedDB** для быстрого доступа, с fallback на JSON файлы из `public/maps/`.

**Источник истины:**
1. **IndexedDB** (приоритет) - изменения из редактора автоматически сохраняются
2. **JSON файлы** (`public/maps/*.json`) - резервная копия, используется при первой загрузке

**Архитектура:**
- **MapManager** - централизованная загрузка карт (IndexedDB → JSON fallback)
- **WorldRepository** - CRUD операции с тайлами и метаданными карт
- **tilemapDataConverter** - конвертация между форматами редактора и игры

### Шаг 1: Создание/редактирование карты

1. **Запусти проект:**
   ```bash
   npm run dev
   ```

2. **Переключись в режим редактора:**
   - Открой приложение в браузере
   - Нажми кнопку **"Редактор"** в верхнем левом углу

3. **Выбери тайлсет:**
   - В левой панели редактора выбери нужный тайлсет (например, "Grass Biome")
   - Используй стандартные тайлсеты для визуального оформления

4. **Используй логические тайлсеты:**

   **Collision Layer** (красный/зеленый):
   - Тайл 0 (прозрачный) - использовать метаданные тайлсета
   - Тайл 1 (красный) - непроходимый
   - Тайл 2 (желтый) - частично проходимый (пока не используется)
   - Тайл 3 (зеленый) - явно проходимый

   **Triggers Layer** (интерактивные зоны):
   - Тайл 0 - bonfire (костер)
   - Тайл 1 - trap (ловушка)
   - Тайл 2 - lava (лава)
   - Тайл 3 - merchant (торговец)
   - Тайл 4 - portal (портал)
   - Тайл 5 - chest (сундук)
   - Тайл 6 - npc_spawn (спавн NPC)
   - Тайл 7 - enemy_spawn (спавн врагов)

   **Time Layers** (временные слои):
   - Тайл 0 - past (прошлое, янтарный)
   - Тайл 1 - present (настоящее, зеленый)
   - Тайл 2 - future (будущее, фиолетовый)

5. **Автосохранение:**
   - Изменения автоматически сохраняются в IndexedDB каждые 2 секунды
   - Индикатор "Сохранение..." / "Сохранено" показывает статус

### Шаг 2: Применение изменений к игре

1. **Нажми кнопку "🎮 Применить к игре"** в интерфейсе редактора
   - Изменения немедленно отобразятся в игре
   - Данные сохранятся в IndexedDB

2. **Проверь изменения:**
   - Переключись в режим "Игра"
   - Проверь визуальное отображение и коллизии
   - При необходимости вернись в редактор для корректировок

### Шаг 3: Экспорт JSON для репозитория

**Зачем это нужно:**
Экспортированный JSON становится новым источником истины для новых игроков. Существующие сохранения продолжат использовать данные из IndexedDB.

**Процесс экспорта:**

1. **Нажми "📥 Export as JSON"** в интерфейсе редактора
   - Файл `interdest_map.json` автоматически скачается

2. **Замени файл в проекте:**
   ```bash
   # Переместить скачанный файл в папку карт
   mv ~/Downloads/interdest_map.json public/maps/interdest_map.json
   ```

3. **Закоммить изменения:**
   ```bash
   git add public/maps/interdest_map.json
   git commit -m "Update world map: [описание изменений]

   Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
   git push
   ```

### Шаг 4: Создание новых карт (города, подземелья)

**Для создания новой карты:**

1. **Создай JSON файл:**
   - Используй редактор для создания новой карты
   - Экспортируй как JSON
   - Сохрани в `public/maps/` с уникальным именем (например, `town_1.json`, `dungeon_level_2.json`)

2. **Зарегистрируй карту в MapManager:**

   В коде где происходит переход на новый уровень (например, `useGameState.ts`):

   ```typescript
   // Загрузка карты города
   const townMapData = await MapManager.loadMap(
     'town_1',                    // Уникальный mapId
     '/maps/town_1.json'          // Путь к JSON файлу
   );
   ```

3. **Используй в игре:**
   - MapManager автоматически сохранит карту в IndexedDB при первой загрузке
   - Последующие загрузки будут использовать IndexedDB
   - JSON файл будет использоваться только для новых игроков

### Приоритет коллизий (3 уровня)

Система определяет проходимость тайлов в следующем порядке:

1. **ПРИОРИТЕТ 1:** Ручное переопределение из Collision Layer
   - Если установлен логический тайл из `collision.png` - используется его значение

2. **ПРИОРИТЕТ 2:** Метаданные тайлсета
   - Если в метаданных тайлсета указано `passable: false/true` - используется это значение

3. **ПРИОРИТЕТ 3:** Fallback по типу ячейки
   - Если тип ячейки (`type`) находится в `SOLID_TILE_TYPES` - тайл непроходимый

**Пример использования:**
```typescript
// Пример метаданных тайлсета (автоматически)
{
  "32:5": { "passable": false }  // Тайл непроходим по метаданным
}

// Ручное переопределение в редакторе
// Используй Collision Layer (зеленый тайл) -> passable = true
// Теперь игрок может пройти, несмотря на метаданные
```

### Синхронизация редактора и игры

**EventBridge координирует обновления:**

1. Редактор отправляет изменения через `EventBridge.emit('editor:mapUpdated', data)`
2. WorldScene получает событие и обновляет TileMap
3. WorldScene сохраняет изменения в IndexedDB через `MapManager.saveMap()`
4. Состояние синхронизировано: Редактор ↔ Игра ↔ IndexedDB

**Важно:** Всегда используй кнопку "🎮 Применить к игре" для синхронизации изменений.
